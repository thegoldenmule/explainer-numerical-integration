What the plan decides

  • Each checkpoint is its own row in the spine grid, routed as #/N/check, so "scroll down and it prompts you" is literal. The table in the doc enumerates every shell touch point, including the trap that a check row must not be modeled as a side pane, since that would lock vertical scrolling.

Two things left open on purpose

  • Hosting is undecided. The repo has no remote and no deploy config, so the doc gives both paths: the Node process as-is, or a static host plus one serverless function using the same grading module.
